# Главная администратора — редизайн и проверка логики

Дата: 14 сентября 2026. Локальная версия: http://127.0.0.1:3002/admin/dashboard.

## Что изменилось

- Главная стала рабочим экраном «Сегодня в клубе»: краткая сводка, полный список занятий дня, пробные сегодня, очередь внимания и состояние филиала.
- Единая спокойная визуальная система с лидами и пробными: компактные строки, небольшие заголовки, один основной CTA «Новый лид», вторичные переходы вместо повторяющихся больших кнопок.
- Занятия и сигналы открываются в боковом быстром просмотре; пробные используют существующий просмотр с разрешёнными сервером действиями. Закрытие по Escape возвращает фокус на открывшую кнопку.
- Вкладки занятий: все, впереди, не закрыты. Завершённые и отменённые не считаются предстоящими. Никакого скрытого обрезания до четырёх записей.
- Очередь объединяет сигналы и риски без повторов, но сохраняет отдельные проблемные группы. Видны просрочки, новые лиды без контакта, сроки продления договоров и отмены.
- Аналитика расположена ниже операционной работы. Все восемь стадий лидов отображаются с периодом создания за 28 дней. Переход сохраняет период и стадию. Для перехода из сегодняшнего счётчика добавлен фильтр «Сегодня» в лидах.
- Динамика за семь дней представлена таблицей: лиды, занятия и оплаты имеют отдельные подписанные колонки, не общую несопоставимую шкалу.

## Исправления данных

| Дефект | Исправление |
| --- | --- |
| Ошибка API выглядела как нули и отсутствие задач | Отдельная ошибка с повтором; при неудачном обновлении сохраняется явно помеченный устаревший снимок |
| Дата определялась через UTC, часовой пояс — устройством | Дата и время Алматы; смена дня обновляет экран автоматически |
| Старый ответ мог относиться к другому филиалу/дню | Проверка метаданных и изоляция состояния по филиалу и дате |
| Занятия зависели от текущего назначения тренера и активности группы | Чтение фактических занятий всех групп выбранного филиала, включая заменяющих/бывших тренеров |
| Посещаемость считалась по занятиям с хотя бы одним присутствовавшим | Процент присутствовавших среди всех отмеченных учеников; 4 из 5 = 80%, а не 100% |
| Сигнал первого контакта учитывал исторические задержки уже обработанных лидов | Новые лиды без записанного контакта старше двух часов, без ограничения историей последних 28 дней |
| Не было просроченных запланированных действий по лидам | Отдельный сигнал для активных лидов с прошедшим nextActionAt; закрытые исключены |
| Поступления визуально представлялись количеством платежей | Основное значение — сумма в тенге, количество отдельно в подписи |
| Переходы использовали API-маршруты и несуществующие фильтры | Рабочие маршруты занятий и поддерживаемые фильтры лидов/договоров |
| Пробные отсутствовали на главной | Пакетное чтение пробных по занятиям выбранного филиала за день |

Существующие шадcn-компоненты Card, ToggleGroup, Table и ModalShell использованы без новой UI-библиотеки. По правилам архитектуры Soccer Hub межмодульные чтения идут через порты владельцев CRM, Coach и Trial; новых сущностей и миграций для этой задачи нет.

## Проверки

- TypeScript: успешно.
- Production build: успешно; VITE_API_BASE_URL=/api для локального прокси.
- Frontend: 94 теста в 12 файлах, все прошли.
- Backend: 250 тестов в 59 наборах, все прошли.
- Playwright: 36 прошли, 2 намеренно пропущены. Пропуски — один сценарий записи в реальные данные лидов на каждом размере экрана; E2E_ALLOW_WRITES не включался.
- Главная: 10 браузерных проверок на desktop 1440×1000 и мобильном Chromium с профилем iPhone 13. Проверены полный список, фильтры, суммы, быстрый просмотр, возврат фокуса, пробные, пустой день, ошибка/повтор, устаревший снимок, отклонение неверного филиала и переход через полночь Алматы.
- Регрессия: лиды, пробные, календарь, основные разделы админки.
- Axe WCAG 2 A/AA + 2.1 AA: нарушений в проверенных состояниях не обнаружено. Горизонтального переполнения страницы не обнаружено.
- В реальном чтении главной JavaScript-ошибок не обнаружено.
- Три последовательных локальных запроса summary после прогрева: 68, 55, 50 мс. Это время ответа локального API, не замер production, холодной загрузки или нагрузки.
- git diff --check: успешно в обоих репозиториях.

## Границы проверки

- Реальные бизнес-записи в браузерных сценариях не менялись; сценарии изменения пробных и занятий проверялись на моках.
- На главной показаны пробные по дню занятия, включая отменённые записи в истории списка. Основной счётчик исключает отменённые. Контакты по пробным прошлых дней остаются в реестре пробных.
- Сигналы групп, тренеров и договоров ведут в соответствующие разделы; это агрегаты, не отдельные редактируемые задачи. Договоры открываются с фильтром ACTIVE, не с несуществующим ending-soon.
- Посещаемость — только среди уже отмеченных учеников; отсутствие отметок показано прочерком, а не нулём.
- Операционные сигналы контактов относятся к текущему состоянию; историческая аналитика лидов явно отделена периодом.
- Это локальная проверка в Chromium, не полный кроссбраузерный или нагрузочный аудит. Ничего не публиковалось в production.

Скриншоты и подробности браузерного прогона: playwright-report/index.html и test-results/. Эти артефакты перезаписываются следующим прогоном.
