Ниже сохранены результаты исходного аудита и шаги воспроизведения.

## Статус и границы исходной проверки

Регресс **не завершён**: браузерный вход под существующей QA учёткой `codex.dispatcher@qa.soccerhub.test` закончился ошибкой. Пароль взят из локального исключённого из git файла; учётка не пересоздавалась и пароль не менялся. Backend ранее выключен по просьбе пользователя. Запрошено разрешение на его запуск, ответа на момент составления отчёта нет.

В браузере проверен только вход. Страницы после авторизации, адаптивность, реальные суммы, сохранение форм, назначение прав, архивирование и восстановление **не считаются проверенными**. Моки не использовались вместо реального входа. Бизнес-данные не изменялись.

В коде просмотрены layout и область просмотра, dashboard, списки учеников/договоров/оплат/долгов, лиды, клубы и филиалы, администраторы, тренеры, права и профиль; также соответствующие серверные сервисы и проекции.

## Найденные проблемы

Все пункты ниже имеют приоритет P2. Кроме №1, они подтверждены анализом кода; для них ещё нужна проверка на живом стенде.

### 1. Серверная ошибка входа выглядит как ошибка пароля

**Источник:** `src/modules/auth/Login.tsx`, обработчик `catch`.

**Проверка:** вход с сохранённой QA учёткой. В браузере получено «Не удалось войти. Проверьте email и пароль». Код выдаёт этот текст для любых исключений, включая сетевые ошибки и 5xx.

**Результат:** пользователь может зря менять верный пароль. Нужно различать отказ авторизации и недоступность сервера; оставить введённый email и предоставить повторную попытку.

### 2. Некорректная дата в URL страницы оплат может обрушить страницу

**Источники:** `company/CompanyListPage.tsx`, `company/company.api.ts`.

**Воспроизведение:** открыть `/dispatcher/payments?dateFrom=bad&dateTo=2026-10-10`. Даты берутся из URL без нормализации. Сводка применённого периода вызывает `dateLabel(from)` до условного отображения ошибки валидации. `Intl.DateTimeFormat.format` получает Invalid Date и выбрасывает RangeError.

**Ожидается:** сообщение о некорректном периоде с возможностью исправить или сбросить фильтр.

### 3. Переход с показателей полученных оплат открывает также отменённые оплаты

**Источники:** `Dashboard.tsx`, серверный `CompanyPaymentReader`.

**Воспроизведение:** при наличии PAID и CANCELLED оплат за период нажать «Выручка» или «Оплаты». Показатели считаются только по PAID, но переход передаёт только даты, без `status=PAID`.

**Результат:** число и состав строк не соответствуют показателю, с которого выполнен переход. Нужен статус полученных оплат в ссылке либо явное объяснение расширения выборки.

### 4. Переход из «Требуют внимания» теряет условие проблемы

**Источник:** `Dashboard.tsx`, массив `issues` и `open`.

**Воспроизведение:** нажать «Открыть раздел» у лидов без администратора, просроченных задач или договоров, заканчивающихся за 14 дней.

**Результат:** выбирается филиал, но открывается весь список лидов/договоров без соответствующего фильтра. Для двух категорий лидов текущий портал вообще не предлагает нужный фильтр, поэтому руководитель не может выделить записи из предупреждения.

### 5. Из архивного филиала «Новый лид» автоматически выбирает другой филиал

**Источник:** `leads/DispatcherLeadsPage.tsx`, `createBranchId`.

**Воспроизведение:** выбрать архивный филиал в области просмотра и нажать «Новый лид», если у компании есть активные филиалы.

**Результат по коду:** архивного филиала нет среди доступных для создания; вместо него заранее выбирается первый активный филиал. В форме выбор виден, но действие из контекста архива неожиданно переключает рабочую площадку. Следует отключить создание для архива с пояснением либо потребовать явный выбор филиала.

### 6. Созданный лид остаётся скрытым старым фильтром дат

**Источники:** `leads/DispatcherLeadsPage.tsx`, обработчик `created`.

**Воспроизведение:** открыть лиды за прошедший период, создать новую заявку сегодняшней датой.

**Результат по коду:** после сохранения сбрасываются поиск и статус, но остаются `dateFrom/dateTo`; новая заявка не появляется в списке. Нужно предложить открыть созданную заявку или явно показать, что она вне выбранного периода.

### 7. Список лидов не восстанавливает страницу при уменьшении числа страниц

**Источник:** `leads/DispatcherLeadsPage.tsx`, состояние `page`.

**Воспроизведение:** на последней странице изменить данные через администратора/другую сессию так, чтобы последняя страница исчезла; обновить лиды.

**Результат по коду:** `page` не ограничивается новым `totalPages`. Пустой ответ показывает «Лидов пока нет», а кнопки пагинации скрыты, хотя предыдущие страницы содержат записи. В `CompanyListPage` и `CoachesPage` такая корректировка уже есть.

### 8. Поиск лидов допускает запрос длиннее серверного лимита

**Источники:** `leads/DispatcherLeadsPage.tsx`, серверный `DispatcherCompanyService.query`.

**Воспроизведение:** вставить в поиск более 200 символов.

**Результат по коду:** поле не ограничено `maxLength`, backend отклоняет запрос, интерфейс показывает общее «Не удалось загрузить лиды» вместо ошибки поискового запроса. В общих списках и тренерах ограничение 200 символов уже предусмотрено.
