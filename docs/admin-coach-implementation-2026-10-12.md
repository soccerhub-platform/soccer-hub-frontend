# Админка и тренер: реализация 12 октября 2026

Реализованы рабочие процессы из плана: общий пробный процесс, задачи филиала, сопровождение договоров, задолженность, загрузка групп, история ученика, кабинет тренера и аналитика.

## Администратор

- Новые разделы: **Задачи**, **Задолженность**, **Загрузка групп**, **Отчёты**. Все запросы ограничены выбранным доступным филиалом на сервере.
- Задачи: весь филиал / мои; лиды, договоры, пробные; сегодня, просроченные и без ответственного; поиск по лидам и договорам. Фильтры и страница сохраняются в URL. Ответственный ограничивает выборку до подсчёта и пагинации.
- Рекомендация тренера по посещённому пробному создаёт работу «Обработать рекомендацию». Решение администратора закрывает эту работу либо заменяет её повторным контактом со сроком.
- В договор добавлена вкладка **Сопровождение**: ответственный, план, контакт, результат, обещанная оплата и общая история. Используются те же данные, что в dispatcher.
- Задолженность: серверные поиск, статус, сортировка и пагинация. Остаток суммируется по всему найденному набору отдельно по валютам; обещания оплаты сегодня и договоры, истекающие за 14 дней, показываются по филиалу.
- Частичная оплата сохраняет обещание открытым. Полное погашение закрывает действие обещания с записью в журнале и увеличением версии. Повторное событие не создаёт второй записи; новый план продления не закрывается оплатой. Запись платежа сериализуется по договору до записи платежа.
- Пробные: период, включая «за всё время» и будущие даты; фильтры посещения и коммерческого результата; сортировка до пагинации; сводка всего периода; единый журнал в деталях. Поиск и «требуют внимания» в существующем реестре остаются явно обозначенными фильтрами текущей страницы.
- В ученике добавлена **Общая история**: договоры, оплаты, лиды, пробные, рекомендации и контакты по точному ID ученика. Дети одного клиента не объединяются.
- Существующие режимы канбан / список, фильтры ответственного, срока, типа и периода в лидах сохранены. Существующие календарь и проверка конфликтов расписания используются без параллельной реализации.

## Тренер

- **Сегодня**: мобильные карточки, неотмеченные ученики, отчёты и пробные без рекомендации; фильтры группы и статуса.
- **История**: все даты без искусственного нижнего предела, группа, статус, готовность отчёта, сортировка и настоящая пагинация по 20 записей. Компьютер — таблица; телефон — краткие строки.
- Сводка и графики готовности отчётов, посещаемости и занятий по группам рассчитываются по всей выбранной выборке. Посещаемость учитывает только сохранённые отметки постоянных учеников и исключает отменённые занятия; финансовых данных нет.
- **Расписание**: период до 31 дня и фильтр группы. «За всё время» используется в истории, а не в оперативном календаре.
- Сохранение отдельного пробного, посещаемости или отчёта сохраняет остальные черновики. При ошибке/409 данные формы остаются; обновление карточки выполняется явно.
- Завершение занятия требует посещаемости постоянных и пробных учеников и темы отчёта. Перед завершением сохраняются изменённые отметки пробных.
- Тренер видит, ждёт ли рекомендация решения администратора, и зафиксированный коммерческий итог; изменение отключено при отсутствии прав.

## Общие правила

- Операции пробного проходят через владельца trial. Admin и coach передают ожидаемую версию; dispatcher делегирует этому же владельцу. Используется блокировка строки, `@Version`, единый журнал с автором и ответ 409 при устаревшей форме.
- Журнал содержит создание, перенос, отмену, посещение, рекомендацию, результат и связывание с оформленным учеником. Конвертация привязана к точному участнику лида; для посещённого пробного фиксируется реальное зачисление.
- Раннее посещение отклоняется в trial. Рекомендуемая группа проверяется по филиалу и вместимости. Вместимость при записи/переносе проверяется также для ещё не конвертированного участника. Лид, ученик и пробное должны принадлежать одному филиалу.
- Чужой филиал, чужое занятие и отключённый сотрудник недоступны. Общие очереди, история и отчёты требуют соответствующего набора прав; графики посещаемости в отчётах требуют также просмотра расписания.
- Бизнес-календарь и сроки — Asia/Almaty. Платёжная форма больше не подставляет UTC как местное время.
- Общие компоненты оформления, периода и MUI X Charts находятся в `shared/operations`; API админки и тренера остаются собственными.

## Проверка

- Backend: **328 тестов**, без ошибок и пропусков. Новые проверки: HTTP-валидация и права, филиалы, версии, будущие сроки, вместимость, обработка рекомендаций, точный участник конвертации, частичная/полная оплата и сохранение истории, SQL-агрегаты и фильтры до пагинации. SQL-проверки используют H2 в режиме PostgreSQL; это не проверка рабочей PostgreSQL.
- Frontend: **150 Vitest**, TypeScript и production build прошли. ESLint: 0 ошибок и предупреждений. Перед merge выполнен security audit: уязвимости не обнаружены.
- Браузер: **20 desktop/mobile сценариев** с подменённым API — администратор, тренер и регрессия dispatcher. Проверены формы, версии, сохранение черновиков, сроки Алматы, полночь UTC, пагинация, фильтры, графики, WCAG и ширина телефона. Скриншоты отчётов и истории просмотрены.

## Запуск и границы проверки

Для новых API требуется перезапуск backend с текущим кодом и обновление frontend. Используются ранее добавленные таблицы журнала, сопровождения и версии; новых миграций именно эта доработка не добавляет. Обычный запуск должен применить общий Liquibase changelog репозитория.

Запущенный локальный backend не перезапускался, рабочие бизнес-записи не менялись. Полная цепочка записи между тремя реальными кабинетами на отдельной QA PostgreSQL и фактическая доставка существующих уведомлений ещё не проверены. Автоматические тесты не подтверждают доставку уведомлений.
