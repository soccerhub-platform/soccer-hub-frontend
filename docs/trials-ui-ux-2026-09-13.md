# Пробные: единый стиль записей и проверка сценариев

Дата: 13 сентября 2026. Локальная версия: [Пробные занятия](http://127.0.0.1:3002/admin/trials). В production изменения не публиковались.

## Дизайн и ориентиры

Основой оставлен существующий интерфейс лидов: компактные строки, нейтральные поверхности, небольшие статусные метки, спокойная типографика и боковой просмотр.

- **Attio:** просмотр справа, выделение выбранной записи и переход к соседней записи без ухода из списка. Применены быстрый просмотр пробного, стрелки «предыдущее / следующее», переход в полную карточку и действия непосредственно из просмотра. [Описание просмотра записей в Attio](https://attio.com/help/reference/managing-your-data/records/create-and-view-records).
- **Linear:** снижение визуального шума, более компактная навигация и менее заметные разделители. Убраны крупные KPI-карточки, повторение этапов в деталях, дубли кнопок и избыточные подписи в строках. [Обновление визуального языка Linear](https://linear.app/now/behind-the-latest-design-refresh).
- **Pipedrive:** связь состояния записи со следующим действием и сроком контакта. В реестре и просмотре показан следующий шаг; просроченный повторный контакт выделяется текстом и цветом. В полной карточке основной шаг находится в отдельном рабочем блоке. [Управление следующими действиями в Pipedrive](https://www.pipedrive.com/en/features/pipeline-management).

Это адаптация принципов к Soccer Hub, а не копирование целого интерфейса другого продукта. Изменения текущего этапа относятся к пробным; остальные разделы админки не объявляются полностью переработанными.

## Что изменилось

1. Реестр: четыре представления по статусу, компактная таблица на desktop, карточки на телефоне, поиск по имени/контакту/группе/тренеру и фильтр внимания. Поиск и внимание действуют на текущей странице — это явно подписано. Общий счётчик по статусу берётся из серверной пагинации.
2. Имя открывает быстрый просмотр. Стрелка в строке и «Полная карточка» открывают детали. Возврат сохраняет статус, страницу и локальные фильтры. Неподходящий номер страницы корректируется по ответу сервера.
3. Детали: занятие, посещение, результат и контакт без повторяющихся блоков этапов. Основное действие доступно один раз; дополнительные — в меню. Пустое меню для закрытых записей не показывается.
4. Перенос: поиск доступных занятий той же группы интервалами по 14 дней, выбор даты, повтор загрузки, исключение текущего, прошедших и отменённых занятий. Запись не меняется до подтверждения.
5. Посещение: понятный выбор «Был на занятии / Не пришёл», комментарий, пояснение последствия. После неявки результат посещённого пробного не предлагается, если сервер его запрещает.
6. Результат: четыре варианта с пояснениями, сохранённые значения при повторном открытии, рекомендованная группа, комментарий и обязательный будущий срок для повторного контакта. Метка «Конвертирован» не представлена как операция создания клиента или договора.
7. Отмена: обязательная причина, явное пояснение, что отменяется только пробное ученика, а не групповое занятие.
8. Все четыре формы используют единое модальное окно, контекст ученика и занятия, закреплённые действия, блокировку повторных отправок и ошибки рядом с полями. Исправленное поле больше не сохраняет устаревшую ошибку.

Правила `shadcn` повлияли на композицию существующих Dialog, Table, ToggleGroup, RadioGroup и полей с доступными названиями. API этих компонентов сверены с [официальной документацией shadcn](https://ui.shadcn.com/docs/components/dialog). Правила `soccer-hub-architecture` сохранены: новые серверные доменные правила не переносились в UI, команды отправляются через существующий TrialsApi, доступность действий проверяется по свежему ответу сервера. Серверный код в этом этапе не изменялся.

## Исправления поведения

- Форматирование дат и сроков использует Asia/Almaty независимо от часового пояса устройства, включая значения с UTC-смещением.
- Будущее пробное без отметки не считается просроченным. Отменённые записи не попадают в локальную очередь внимания.
- Перед командой повторно загружаются capabilities. Изменившееся состояние блокирует действие и объясняется в форме.
- Ошибки 409/503 сохраняют черновик; повтор не требует заполнения заново.
- Ответы устаревших запросов списка и выбора занятий игнорируются.
- Параметр возврата ограничен локальным реестром пробных.

Полный прогон также включил ранее существовавшие проверки лидов, расписания и навигации админки.

Вход, чтение реестра и открытие реальных записей проверены на локальном backend. Изменяющие сценарии пробных проверены с подменой ответов API: реальные записи ради этого прогона не переносились, не отменялись и не завершались. Два пропущенных теста — существующий workflow лида на desktop/mobile, требующий разрешения записи `E2E_ALLOW_WRITES`. Сквозная запись в БД, отправка звонков/писем, Safari, производственная нагрузка и полная ручная проверка со скринридером в этот прогон не входили.

Первый запуск браузерных тестов выявил неверный API-адрес в локальной сборке: использовался порт 8080 вместо рабочего прокси к 8081. Итоговая сборка выполнена с `VITE_API_BASE_URL=/api`; локальный вход и чтение прошли повторный прогон.

## Границы этапа

- Глобальный поиск и фильтр внимания по всем страницам требуют расширения серверного API. Сейчас область фильтрации указана явно.
- «Записать из лида» ведёт в существующий процесс записи из карточки лида; отдельный универсальный мастер создания пробного здесь не добавлен.
- Изменялись четыре модальных сценария пробного. Мастер назначения пробного в лидах уже использует стиль лидов и в этом этапе не переписывался.
- Существующие правила переходов и ограничения сервера сохранены; это не полная повторная сертификация бизнес-логики backend.
